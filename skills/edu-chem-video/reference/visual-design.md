# 讲解动画设计（写 storyboard.md 和 anim.js 之前必读）

## 目标：方程式在讲题，守恒被"数"出来

差的做法：顶部写好方程式，下面一行行抄算式。`render.mjs motion` 会把这种句子标成 `STATIC` / `POP`。

好的做法：**每句旁白，画面上都有一个动作把这句化学推理演出来**。说"铜升两价"，就让 Cu 标记在化合价数轴上从 0 滑到 +2；说"最小公倍数是 6"，就让两排电子一组一组长到一样长；说"转化量按系数比"，就让系数从方程式飞进三段式；说"6 个起酸性作用"，就让 6 个 HNO₃ 分子滑进硝酸铜那一堆。

## 本技能的画面风格（和数学 / 物理视频区分开）

| | 数学（edu-math-video） | 物理（edu-physics-video） | **化学（本技能）** |
|---|---|---|---|
| 背景 | 米色方格笔记本 | 深蓝工程蓝图 | **墨绿黑板 + 粉笔灰 + 木质粉笔槽** |
| 线条 | 手绘墨水 | 细直工程线、发光光线 | **粉笔线（`chalk()`，更抖）** |
| 版面 | 左图右板 | 左图右板 | **顶部方程式条（全宽）+ 左下演示区 + 右下石板** |
| 主角 | 几何图形 | 力、运动、图像 | **方程式、化合价、电子、分子、表格** |

## 颜色约定（整部视频不变；与双线桥一致）

| 颜色 | 含义 |
|---|---|
| 蓝 `C.blue` | 化合价升高 / 失电子 / 被氧化 / 还原剂；反应物计数 |
| 红 `C.red` | 化合价降低 / 得电子 / 被还原 / 氧化剂；生成物计数 |
| 黄 `C.yellow` | 系数、关键数字、答案框、电子 |
| 橙 `C.orange` | 物质的量（mol）数值 |
| 绿 `C.green` | 守恒成立 ✓、平衡行、结论 |
| 紫 `C.purple` | 换算因子（÷M、×V_m、÷V）、Δt |
| 灰 `C.gray` | 标签、表头、辅助线 |

## 每句旁白的四个动作：指 → 动 → 留 → 连

| | 做什么 | 怎么写 |
|---|---|---|
| **指** | 旁白提到的物质 / 元素被点亮 | 方程式里：`glow([[it.x0, EQY], [it.x1, EQY]], col, bump(...), 60)`；intro 用 `hiBox` |
| **动** | 一个体现化学推理的动作 | 见下表 |
| **留** | 化合价、系数、桥、表格数值、✓ | `valence`、`equation({pop})`、`bridge`、`iceTable`、`tally` |
| **连** | 板子与画面同色（失 = 蓝、得 = 红、mol = 橙） | `bm(i, '...', t, lt, { c })` |

## 动作表：化学 → 动画

| 化学 / 说法 | 画面动作 | 代码 |
|---|---|---|
| 写出方程式 | 方程式从左到右逐项写出，粉笔下划线扫过 | `equation(spec, 960, EQY, {p})` + `chalk([...], {p})` |
| 标化合价 | 化合价数字在元素上方弹出；化合价数轴上标记滑动（升 / 降） | `valence(eqX(it, 'N'), EQY, '+5', p, col)` + `token` 沿数轴移动 |
| 电子守恒（最小公倍数） | 失 / 得两排电子按每组 2 个、3 个交替增长，直到等长 | 见 template `SC.balance` |
| 定系数 | 组数从电子行飞进方程式系数位置，系数弹出 | `flyText('3', from, [it.kx, EQY], e)` + `equation({pop})` |
| 原子守恒 | 计数条左右生长，数值计数，相等打 ✓ | `tally(x, y, rows, {hi})`（传动画中的值） |
| 双线桥 / 单线桥 | 桥线从一个元素画到另一个元素，电子沿桥流动 | `bridge(a, b, '失去 3×2e^-', p, {side, c})` + `eFlow(path, a)` |
| 电子转移总数 | 电子一个个从"失"框飞到"得"框，计数 | `along(quadPts(...), e)` |
| 物质的量换算 | 节点之间箭头上的光点移动，目标节点数值计数 | `molMap(...{hi})` 或 template 的 `node` / `link` |
| 系数比 | 方程式里的两个系数飞下来组成 "3 : 2" | `flyText` |
| 三段式 | 表格逐线画出；起始行弹出；系数飞进转化行；平衡行做减法 | `iceTable(...{rev})` |
| 微观反应 | 分子盒里分子游动，按系数比消失 / 出现 | `particles(box, [{name, n}])`（n 随进度变化） |
| 浓度 / 速率 | c-t 曲线随时间生长，Δc、Δt 箭头画出 | `graph()` → `curve` + `arrow` |
| 平衡常数 | 平衡浓度从表格飞进 K 表达式，结果计数 | `flyText` + `countTo` |
| 转化率 / 产率 | 条形图转化部分生长，百分数计数 | `fillPts` + `countTo` |
| 区分作用（被还原 vs 酸性） | 分子分流进两个"堆"，数量一目了然 | `molecule` + `mix2` |
| 气体生成 / 沉淀 | 烧杯里冒泡 / 沉淀落下 | `beaker` + `bubbles` |
| 代入数值 | 数值飞进板子算式 | `flyText(str, from, blPos(row, dx), e)` |
| 答案 | 盖章 + 答案框 | `stamp`、`bbox` |

## 两个完整示例
- `template/`：氧化还原（铜与稀硝酸）：化合价数轴、电子分组配平、原子计数、双线桥、物质的量转化链、2 + 6 分流。
- `examples/equilibrium/`：化学平衡三段式：分子盒按比例反应、三段式逐行填、c-t 曲线、浓度代入 K、转化率条。

## motion 检查查不出来、你必须自己守住的
- **化学正确性**：化合价、系数、桥的起止元素、电子数、单位，截图逐项核对。错一个化合价比动画难看严重得多。
- **方程式先配平再用**：系数从 `chem_check.py` 的结果来；画面里所有比例从系数来。
- **微观数量与宏观一致**：分子盒里一个分子代表多少 mol 写在盒子下面，转化前后数量与三段式一致。
- **方程式条不要被挡**：y 140~300 只放方程式、化合价、桥；双线桥上方的标签别碰到左上角标签（y < 110）。
- **图形清单**：题目里的物质、条件（足量 / 标况 / 体积）、所求量都要出现。

## 版面与节奏
- 方程式条：`eqStrip(1)` + `equation(spec, 960, EQY)`，`EQY = 222`；桥向上最多到 y≈130，向下最多到 y≈340。
- 演示区 x 60~900、y 310~860；石板 x 930~1870，`bm` 第 0~8 行。演示要更宽时（如双线桥幕的电子飞行），那一幕可以不画石板。
- 每幕开头方程式条保持上一幕结尾的状态（同一个 `eqDraw()`）。

## storyboard.md（写 anim.js 之前必须先写）
格式见 `template/storyboard.md`：顶部写**解题卡**（见 chemistry-solving.md）和**图形清单**，再每句一行 `| 幕id 句号 | 旁白要点 | 指 | 动 | 留 | 板书 |`。
- 除第一幕和最后一幕外，"动"必须填，且是动作表里的动作；只写"出现/显示/亮起/高亮"会被 `--check` 拒绝。
- 每幕至少一句是连续运动（滑动、飞入、电子流动、计数、曲线生长、分子转化）。

`node render.mjs motion`：`STATIC` 必须改；每幕至少一句 `MOVE`。确实不需要动的句子列在 `episode.json` 的 `"static_ok"`，交付时说明理由。
